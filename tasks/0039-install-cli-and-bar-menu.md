# 0039: Make install, the command line and the bar menu safe with GG's files

Status: open
Depends on: none
Spec: REQ-INSTALL-01, REQ-SHELL-02, REQ-ACT-05, REQ-SESSION-07, REQ-LABEL-01, REQ-CLI-01
Goal: Several paths can lose GG's configuration or mislead him. `thodu install` reads `~/.config/hypr/bindings.lua` with `read_to_string(...).unwrap_or_default()` in crates/thodu/src/main.rs, so one byte that is not UTF-8 makes it rewrite the file with only Thodu's lines, and it writes with a plain `std::fs::write`, so a full disk truncates it; the key lookups fall back to defaults the same way. A rerun replaces custom keys written in single quotes or built by concatenation, because `configured_key` reads only a double-quoted key; a Thodu bind split across lines has only its first line replaced, and a file ending in `return` gets lines appended after it, either of which leaves a Lua error and no bindings. Install appends the accessibility `hl.env` lines and runs `hyprctl reload`, but Omarchy copies Hyprland's environment to systemd only at start, so apps launched through `uwsm-app` lack the variables until GG logs in again while `thodu doctor` (it checks only the file text) reports them present; `systemctl --user set-environment` and `dbus-update-activation-environment` during install would apply them now. The unit can get a bare `ExecStart=thodud` when the two binaries are not side by side, and a path with a space or `%` breaks it. In the bar menu, Enter on a disabled row is dispatched (`BarMenu.qml`) and `openConfig` in BarProbe.qml has no `configReady` guard, so with an unreadable config the "Edit to fix settings" row writes the defaults over it; a failed `setText` is silent. Bad arguments exit 1 rather than 2 (`thodu key`, `close`, `--hints-key` without `--grid-key`, invalid key characters); an invalid `--scope` is not checked; `--window` or `--scope` with no value and misspelled flags are ignored, so `thodu hints --window` runs on every window; `bench` prints "ERROR ERROR". `crates/thodu/build.rs` panics on a symlink under components/ or lib/ (an editor lock file) and embeds any untracked file there. While thodud is down, BarProbe.qml makes a new socket every second and Client.qml logs each failure, about 86 thousand journal lines a day. A config file that cannot be read or is not UTF-8 silently gives the defaults, and a type error does not name its key. In scroll mode Backspace from "05" to "0" keeps area 5 focused while the shown prefix means area 10. Label capacity is safe only by coincidence: `assign_beneath` reaches four letters at 677 image targets and nothing ties the detector's 500 cap to that limit. Fix each so GG's files survive any input, the environment applies at install, errors name what to do, and the limits are tied together in code.

Acceptance:
- run: `tests/acceptance/reqs.sh REQ-INSTALL-01 REQ-SHELL-02 REQ-ACT-05 REQ-SESSION-07 REQ-LABEL-01 REQ-CLI-01`
- scenario: on a fake home, a `bindings.lua` that is not UTF-8, uses single-quoted or concatenated keys, splits a bind across lines or ends in `return` survives install with GG's lines intact and valid Lua; the write is atomic.
- scenario: install applies the accessibility variables to the running user session and doctor checks the live environment; the bar menu never writes defaults over a config it could not read.
- scenario: bad arguments exit 2 with an ERROR line saying what to do; scroll Backspace focuses the area its prefix names; the label limit and the image cap are checked together.
